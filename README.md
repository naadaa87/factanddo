## 1. 저장소 구성 — 무엇을 고치면 무엇이 바뀌나

| 경로 | 역할 | 이걸 수정하면 |
|---|---|---|
| `build.py` | 사이트 생성기 (표준 라이브러리만 사용) | 상단 `CONFIG`(도메인·폼주소·이메일·오픈채팅), 페이지 문구·구성 |
| `content_ko.py` | 장문 콘텐츠 | 정책 3종 초안, E0–E5 기준, 평가 7차원, 언어 원칙 |
| `data/services.json` | 탐색 데이터 | 탐색 페이지의 서비스·과정 목록 (형식은 파일 상단 `_스키마` 참고) |
| `assets/style.css` | 디자인 시스템 | 색·타이포·레이아웃 (브랜드 색상은 `:root` 변수) |
| `assets/app.js` | 기능 | 검색·필터, 리뷰 폼, 그룹 보드, 스냅샷 공유 |
| `assets/img/`, `assets/og.png` 등 | 브랜드 이미지 | 로고·일러스트·공유 썸네일·파비콘 (공식 디자인 파일 기반) |
| `dist/` | **빌드 결과물 (자동 생성)** | 직접 수정하지 않음 — `.gitignore`로 커밋 제외 |

로컬 미리보기: `python3 build.py` → `cd dist && python3 -m http.server 8000` → http://localhost:8000
(파일을 더블클릭해 여는 file:// 방식은 절대경로 링크가 막혀 화면이 깨져 보입니다. 위 방법을 쓰세요.)

## 3. Cloudflare Pages 배포

**Git 연결 프로젝트(권장) 빌드 설정**
- Framework preset: `None`
- Build command: `python3 build.py`
- Build output directory: `dist`
- 빌드 실패 시: Pages 프로젝트 → Settings → Variables에 `PYTHON_VERSION = 3.12` 추가 후 Retry

자세한 단계별 안내는 함께 제공된 **『팩트앤두 홈페이지 업로드 가이드』** 문서를 보세요.

## 4. 오픈 전에 CONFIG에서 채울 것 3가지

`build.py` 상단 `CONFIG`:

```python
"BASE_URL": "https://factanddo.pages.dev",  # 도메인 연결 후 https://factanddo.com 으로
"WAITLIST_FORM_URL": "",  # Tally/구글폼 주소를 넣으면 사전등록 버튼 활성화
"CONTACT_EMAIL": "",      # 문의 이메일 (푸터·정책 페이지에 표시)
```

값이 비어 있으면 사이트는 해당 기능을 **'준비 중'으로 정직하게 표시**합니다(가짜 버튼 없음).

## 5. 정직성 원칙 (코드에 반영된 것)

- 허위 평점·이용자 수·후기 수 없음. 표본이 없으면 "표본 없음 / 수집 전"으로 표시
- 비교함·리뷰·그룹 기록은 브라우저(localStorage) 저장임을 화면마다 고지
- 리뷰 제출 시 **관계 공개(이해관계) 필수** — 미선택 시 제출 차단
- E5 표기 옆에 항상 "수익 보장 인증이 아님" 설명 병기
- 그룹 화면 예시 이미지에는 '시안' 라벨 부착

## 6. 이전 베타(✓+▶ 틸 로고 버전)에서 넘어오는 경우

- 이 버전은 **공식 로고·색상(#172238/#315EFB/#FF6B4A)과 E0–E5 체계**로 전면 교체된 빌드입니다. 기존 저장소 파일 위에 그대로 덮어쓰면 됩니다(옛 `services_raw.json` 등 남은 파일은 무시되며 지워도 됩니다).
- 기존 173개 조사 데이터를 되살리려면: 다음 대화에서 옛 데이터 파일(엑셀 또는 services_raw.json)을 올리고 Claude에게 *"data/services.json 형식으로 변환해서 합쳐줘"* 라고 요청하세요.
- 방문자 브라우저에 남아 있던 옛 베타 기록(그룹·후기)은 저장 키가 달라 새 화면에는 나타나지 않습니다.
